Runtime API:
- Define exactly: def cost(features, params):
- features maps each joint-feature name to a torch tensor of shape
  (n_rollouts, horizon) over the future timesteps (the current state is not
  included). Values are radians:
  features["elbow_flexion"]
  features["shoulder_flexion_extension"]
  features["shoulder_abduction_adduction"]
  features["shoulder_elevation"]
  features["shoulder_internal_external_rotation"]
  The shoulder features are preference-friendly component-angle approximations
  in the spine3 frame: flexion/extension is signed upper-arm movement along
  the z axis, abduction/adduction is signed lateral upper-arm movement along
  the x axis (positive is away from the torso for the left arm), and
  internal/external rotation is the signed swing-twist of the anatomical
  shoulder rotation about the T-pose upper-arm axis. Clavicle rotation does not
  contribute. Positive = internal rotation, twisting the forearm toward the
  body midline; negative = external rotation.
  shoulder_elevation is total upper-arm elevation from straight down (0 = arm
  hanging at side, pi/2 = horizontal, pi = overhead); it increases when the arm
  is raised in any direction and is the only feature that can express a height
  limit independent of whether the arm was raised forward or sideways.
- torch is available, and so is interp(x, xp, fp): np.interp for a tensor x,
  linear between the anchor points (xp, fp) and holding the end values outside
  them. Do not import anything.
- The same function also steers motion generation by gradient, so it must be
  differentiable in the features. Build every penalty from a margin, e.g.
  torch.clamp(threshold - x, min=0.0) ** 2, which is zero inside the bound and
  grows past it. Never turn a comparison into a boolean, count or mask, never
  branch on tensor values, and never call .item() or .numpy().
- If you need statistics such as maximum wrist height (y) during the MDM
  trajectory, read those values from the Summaries section below and encode
  them as hardcoded floats or params in your cost function.
- Average over the timesteps (torch.mean(..., dim=1)), never sum: the planner
  and the motion generator evaluate the cost over different numbers of frames.
- Return a finite torch tensor with shape (n_rollouts,).
